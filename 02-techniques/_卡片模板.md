# 技术卡片模板

> 复制本文件，重命名为 `<编号>-<技术名>.md`，逐字段填写。
> **原则：写不出来的字段就留空，不要编。** 卡片的价值在于可复现，不在于填满。

---

## 卡片字段

```markdown
# <技术名>（<英文原名>）

- **所属类别**：A 语境注入 / B 推理激发 / C 结构约束 / D 流程编排 / E 反馈迭代 / F 元层自动化
- **提出方 / 出处**：<论文或官方文档，含链接>
- **首次提出时间**：<年份>

## 机制
<一句话说清它改变了模型的哪个环节。不要描述成"让模型更聪明"。>

## 最小示例
<可直接复制运行的最短提示词，10 行以内>

## 生效条件
- <什么情况下用了有效>
- <...>

## 失效边界
- <什么情况下用了无效甚至有害>
- <...>

## 推理型模型下的差异
<对带 thinking / reasoning 档位的模型，本技术是冗余、有效还是有害？依据是什么？>
<若无实测，标注「待实测」，不要猜测。>

## 跨模型表现
| 模型族 | 表现 | 备注 |
|---|---|---|
| GPT 系 | | |
| Claude 系 | | |
| Gemini 系 | | |
| 国产开源系 | | |

## 关联实验
- <链接到 03-benchmark/ 中的实验编号>

## 参考
- <出处链接>
```

## 待建卡片清单

按优先级排序，逐个补：

**A 语境注入**
- [ ] Zero-shot
- [ ] Few-shot（含示例数量、顺序、分布的影响）
- [ ] 角色 / 人格设定
- [ ] RAG 接地与引用约束

**B 推理激发**
- [ ] Chain-of-Thought
- [ ] Zero-shot CoT
- [ ] Self-Consistency
- [ ] Tree of Thoughts
- [ ] ReAct
- [ ] Reflexion

**C 结构约束**
- [ ] 输出模板
- [ ] JSON Schema / 原生结构化输出
- [ ] 负向提示词（图像生成，独立体系）

**D 流程编排**
- [ ] 任务分解
- [ ] Prompt Chaining
- [ ] 路由分发
- [ ] 工具调用 / Function Calling

**E 反馈迭代**
- [ ] Self-Refine
- [ ] Critique-Revise（分离批评者与生成者）
- [ ] 硬校验回喂

**F 元层自动化**
- [ ] Meta-Prompting
- [ ] APE 自动提示词优化
- [ ] Prompt 版本化与回归测试
