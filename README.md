# Prompt Atlas

**跨 Agent 宿主的提示词资产库与方法论**

一套可复用、可验证、可迁移的提示词工程方法论，外加一个可跨宿主部署的资产库。
目标不是"收集好用提示词"，而是建立**一次编写、多处部署**的一致性资产体系。

---

## 三条主张

这三条是本项目的评判标准，也是区别于"提示词大全"类内容的分界线。

**1. 提示词是接口设计，不是话术。**
每条提示词都必须明确三件事：输入空间（接受什么）、输出契约（产出什么格式）、失败行为（信息不足时怎么答）。能让第三人照着复现出同样结果的，才算交付物。

**2. 没有评测的提示词等于没写。**
每个模板必须绑定可判定的指标——格式合规率、事实准确率、拒答正确率、人工编辑耗时——而不是"感觉变好了"。感觉不进版本记录。

**3. 资产必须跨宿主可迁移。**
同一能力在不同 Agent 宿主上应有确定的部署路径，且核心内容保持一致。只在一个平台上能用的不是资产，是配置。

> 注：第 3 条聚焦的是**宿主间的一致性**，不是"每个模型各写一份提示词"。
> 后者是常见误解——事实上约八成的提示词原则在所有模型上通用，真正需要适配的是档位参数、schema 支持、上下文量级这类架构级差异，而非措辞。详见 `01-taxonomy/01-模型适配矩阵.md`。

## 五层资产模型

项目的核心结构。下层是上层的原料，上层是下层的组合。

| 层 | 名称 | 是什么 | 目录 |
|---|---|---|---|
| **L0** | 元提示词 | 用来**生产**下层资产的提示词，如 Skill 生成器 | `06-meta-prompts/` |
| **L1** | 提示词 | 原子资产，按六类认知机制分类 | `05-templates/` `02-techniques/` |
| **L2** | 技能包 | 提示词 + 流程 + 约束的组合，可被宿主直接加载 | `07-skills/` |
| **L3** | 专家 / 专家团 | 多个技能包 + 人格设定 + 知识边界的复合体 | `08-experts/` |
| **L4** | 宿主适配 | 把上层资产部署到具体 Agent 宿主的转换层 | `09-hosts/` |

**L0 → L3 是生产链**：用元提示词生成提示词，提示词组合成技能包，技能包装配成专家。
**L4 是分发层**：解决"同一套资产在不同宿主上保持一致"的问题，是本项目的差异化所在。

## 方法论基础：六类认知机制

提示词技术按**改变模型的哪个环节**分类，而非按技术名词罗列：

| 类 | 改变的环节 | 解决什么 |
|---|---|---|
| A 语境注入 | 输入信息 | 模型不知道 |
| B 推理激发 | 计算步数 | 模型没算够 |
| C 结构约束 | 输出分布 | 模型没说清 |
| D 流程编排 | 任务拓扑 | 任务太复杂 |
| E 反馈迭代 | 输出质量 | 第一版不够好 |
| F 元层自动化 | 提示词本身 | 手写调不过来 |

详见 `01-taxonomy/00-分类体系.md`。

## 关于术语

本项目统一使用 **Agent 宿主（Agent Host）** 指代各类可加载提示词预设、技能包、专家配置的 AI 应用平台。

该用法源自 MCP（Model Context Protocol）官方架构定义：Host 是承载 AI 模型、管理会话与授权边界的应用层。使用中立术语而非厂商名，是为了让资产定义不绑定任何单一平台。

详见 `09-hosts/00-术语与一致性策略.md`。
