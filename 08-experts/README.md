## 什么是专家

多个技能包 + 人格设定 + 知识边界的复合体。它不是"一个写得好的人设提示词"，而是**有边界、有分工、可组合**的角色定义。

| | L2 技能包 | L3 专家 |
|---|---|---|
| 关注点 | 把一件事做对 | 知道该做哪件事、不该做哪件 |
| 组成 | 指令 + 约束 | 技能组合 + 人格 + 知识边界 + 交接规则 |
| 失效模式 | 输出格式错 | 越界、角色漂移、该拒答时硬答 |

---

## 专家定义的五个要素

缺任何一个，专家配置都会在实践中漂移：

| 要素 | 说明 | 常见缺失后果 |
|---|---|---|
| **角色定位** | 是谁，什么资历，代表谁的立场 | 输出泛泛而谈 |
| **能力清单** | 挂载哪些技能包 | 该会的不会 |
| **知识边界** | 哪些领域内、哪些领域外 | 越界胡答 |
| **行为准则** | 不确定时怎么办、如何表达异议 | 无据硬答、一味迎合 |
| **交接规则** | 何时该转给别的专家或交回人类 | 专家团里职责打架 |

**第五个要素最容易被忽略**，但正是它决定专家团能不能真的协作。只有分工没有交接规则的多专家系统，最终会退化成一个和稀泥的单体。

## 目录约定

```
08-experts/
├── <expert-id>/
│   ├── expert.yaml        # 专家定义（宿主中立）
│   ├── persona.md         # 人格与语气设定
│   └── skills/            # 挂载的技能包（引用 L2，不复制）
└── <team-id>.team.yaml    # 专家团编排：成员 + 路由 + 交接规则
```

**关键约束**：专家通过**引用**挂载 L2 技能包，不复制内容。复制即漂移。

---

## 专家团编排要点

| 要点 | 说明 |
|---|---|
| 成员职责互斥 | 两个专家能做同一件事 = 必然冲突 |
| 路由规则可判定 | "复杂问题给 A"不可判定；"涉及金额计算给 A"才可判定 |
| 交接有显式信号 | 定义清楚什么信号触发交接，而不是靠模型自己感觉 |
| 有兜底成员 | 无人认领时的默认处理者 |
| 有人类回流点 | 定义什么情况下必须交回人类确认 |
